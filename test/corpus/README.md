# Malformed-input corpus *(fork-only)*

Small, committed files of deliberately broken input, one directory per
format. Each format is wired into the host test suite of the parser that
consumes it:

| Directory | Parser under test | Suite |
|-----------|-------------------|-------|
| `json/`   | `StreamingJsonParser`, `ReleaseJsonParser` | `test/streaming_json_parser`, `test/release_json_parser` |
| `xml/`    | in-tree expat (device flags) + `XmlParserUtils` | `test/xml_parser_utils` |
| `css/`    | `CssParser` | `test/css_parser` |
| `html/`   | `ChapterHtmlSlimParser` over in-tree expat (device flags) | `test/chapter_html_slim_parser` |

"Device flags" means the suite compiles `lib/expat/{xmlparse,xmlrole,xmltok}.c` into its own binary
with `XML_GE=0` and `XML_CONTEXT_BYTES=1024`, never the host system's expat. That matters for the
`html/` and `xml/` pins: `XML_GE=0` disables general entities, so an undefined-entity or
external-entity file behaves on the host exactly as it does on the device. `test/opds_parser`
builds the same way, though it does not read from this corpus.

Every file is generated by `scripts/generate_test_corpus.py` from literal
byte strings — regeneration is deterministic and byte-identical. Do not edit
corpus files by hand; edit the generator and re-run it:

```bash
python3 scripts/generate_test_corpus.py
```

## Taxonomy

The filename prefix names the malformation class, one class per file:

| Prefix | Meaning |
|--------|---------|
| `trunc_` | input cut off at a structural boundary (mid-tag, after `{`, after `:`, mid-literal, ...) |
| `unterminated_` | construct opened but never closed (string, comment, CDATA, block, `@`-rule) |
| `deep_` | deeply nested structure (64+ levels; JSON also has the 32-level parser maximum) |
| `huge_` | absurdly large token or numeric value (overflow the fixed buffers / float range) |
| `enc_` | encoding pathologies: invalid UTF-8, embedded NUL bytes, UTF-8/UTF-16 BOM variants |
| `empty_` | zero bytes or whitespace only |
| `mismatch_` | structurally inconsistent input (wrong closers, duplicate attributes, two roots, bare `&`) |
| `release_` | (json only) GitHub-release-shaped payloads with one defect each, for `ReleaseJsonParser` |

## How the suites use the corpus

Each consuming suite has a `<Name>CorpusTest.cpp` with two layers:

1. **Universal invariants** — a gtest value-parameterized test over the
   directory listing (`corpus::listCorpusFiles`, see `CorpusTestSupport.h`).
   Any file dropped into a corpus directory is picked up automatically and
   must: not crash, terminate within a bounded loop/step budget, keep outputs
   inside their fixed buffers, and leave the parser usable (reset/reuse
   parses a canonical valid document correctly afterwards).
2. **Pinned outcomes** — a per-file table asserting what the parser
   *currently* does (accept/reject, error latch, rule count, ...), plus
   focused behavior tests for notable file classes. Tests marked
   "documents a current limitation" pin behavior that is arguably wrong;
   fixing the parser should flip the pin deliberately, not silently.

## Extending

1. Add the byte string to the right table in
   `scripts/generate_test_corpus.py`, using the prefix taxonomy above (new
   prefixes are fine — document them here).
2. Re-run the generator and commit the new file together with the generator
   change.
3. Run the consuming suite: the new file passes the universal invariants
   automatically and the pinned-outcome test reports a **skip** until you add
   the file's entry to the suite's pin table. Add the pin so the skip
   disappears.
